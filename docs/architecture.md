# 系统分工与原理

## 1. 发现候选

程序向公开数据库的 API（程序查询入口）发送检索条件，返回记录编号。关键词匹配只负责形成候选名单，不能证明记录一定是空间实验。

首个版本计划从 NCBI GEO 开始，必要时沿关联查询 SRA。成像类平台的资料可能位于其他官方来源，需要单独适配。

## 2. 读取资料

每个来源使用单独的读取模块，取得研究和样本说明、关联编号以及公开文件清单。查询结果保留来源 URL 和查询日期，便于复查。

## 3. 提取字段

优先直接读取明确的结构化字段。复杂说明可在后续引入现成大语言模型辅助提取；同时保留原文证据和不确定状态。

语言模型通常基于 Transformer。Agent 则是模型选择工具、程序执行工具、结果返回模型的工作循环。数据库检索和文件检查由对应程序执行。项目初始化阶段尚未接入这些模型调用。

## 4. 关联资产与检查空间信息

将表达、坐标、图像、分割和标注作为不同资产记录。相同研究编号不保证来自同一切片；相似文件名不保证逐行对应。

后续校验包括观测 ID、切片身份、坐标单位、参考系和图像变换。真实邻居关系应在对应核实后根据真实坐标计算。源文件只支持 spot 时，不直接标成单细胞。

## 5. 保存与更新

首个版本使用 CSV / JSON，保存状态与证据；后续需要时再接数据库和定时更新。检索词、模型、提示词和处理程序均应记录版本。

scRecounter 的重处理思想可供参考，但空间平台需要各自的处理步骤。只有公开解码结果的成像数据，不能标记为已完成原始成像重解码。
